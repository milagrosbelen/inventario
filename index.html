Vista 1

Cómo se crea un software que aguanta

No es una lista de cursos. Es el camino que tiene que recorrer una petición —por ejemplo una orden en Drivox— sin romperse cuando hay más personas. Si una sola caja hace todo, se satura. Si cada capa hace una cosa, escala.

  1. 01

    Quién lo usa

    Dueño, mecánico, cliente. Sin esto no hay “listo”: solo pantallas.

    • Roles
    • Qué puede hacer cada uno
  2. 02

    Que llegue por internet

    Nombre, dirección y candado. Si solo anda en tu PC, no es un producto.

    • Dominio
    • DNS
    • IP
    • HTTPS
    • Hosting
    • CDN
  3. 03

    Lo que se ve (cliente)

    Web o celular. Dibuja y pide datos. No habla directo con la base.

    • HTML / CSS
    • JavaScript + DOM
    • Fetch / JSON
    • Expo
    • KMP (trabajo)
  4. 04

    Contrato de la API

    Qué se pide, qué vuelve, en qué formato. Sin contrato, frontend y backend se pisan.

    • REST
    • GET POST PUT DELETE
    • JSON
    • Endpoints
    • Async / promesas
  5. 05

    Reglas de negocio (backend)

    Acá vive “se puede crear esta orden”. Login, permisos, validar. Un controlador no puede hacerlo todo.

    • C# / Laravel
    • Capas
    • POO
    • JWT / middleware
    • Sin god controller
  6. 06

    Datos

    Tablas con sentido, claves, consultas. Índices y backups para que no se ponga lenta ni se pierda.

    • Modelo E-R
    • PK / FK
    • SQL
    • EF / Eloquent
    • Triggers / vistas
  7. 07

    Que se pueda cambiar

    Git, pruebas, logs, deploy. Software mantenible = otra persona (o vos en tres meses) puede tocar una pieza.

    • Git / PR
    • Testing
    • Deploy
    • Logs
    • Cache

Requisitos para no perderte

Si falta esto, se rompe

ArquitecturaCada capa una responsabilidad. Es el hueco que más sentís, y ya tocaste capas en C#.
AuthQuién entra y qué ve. Laravel JWT lo viste; hay que ponerlo de punta a punta.
Testing de verdadNo solo la definición de QA. Tres pruebas del flujo que más duele.
Seguridad webHTTPS, no subir claves, validar entradas, tríada CIA y OWASP aplicados.
PerformanceÍndices, no consultar mil veces, cache e invalidar cuando el dato cambia.
Deploy / DevOpsAmbientes y un servidor. El trial de cloud vive acá.
Estado y syncQué hay en pantalla vs qué hay en la base. Async bien usado.
Contrato RESTLo viste con Swagger. Hay que respetarlo en Drivox y en el laburo.

Proyecto · Drivox

El taller de motos

Acá se nota si el diagrama de la vista 1 está o no. Los errores que no querés repetir son capas mezcladas, un controlador dios, y “en mi máquina anda”.

Atención ahora: una próxima acción, no reescribir todo. Ejemplo: un flujo (crear orden) que respete API + reglas + datos, o un test, o un arreglo de seguridad. El trial manda; Drivox no se come las 3 h de KMP.
